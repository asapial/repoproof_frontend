# RepoProof safe MVP frontend

Set `NEXT_PUBLIC_API_BASE_URL` to the backend origin before starting or building the frontend. Local HTTP is accepted only for loopback; non-local backends must use HTTPS. For local development, use matching hostnames on both frontend and backend, such as `http://localhost:3000` and `http://localhost:5000`, and configure the backend allowed origin accordingly. No secret belongs in `NEXT_PUBLIC_*` variables.

The UI uses Better Auth session cookies, displays the authenticated curated catalog, saves or deletes one user-owned selection draft, and sends a run request to the real API. A draft is not a run. While the runner is unavailable, the backend returns `RUNNER_UNAVAILABLE`; no run or verification verdict is created. Full run lifecycle, reports and independent runner isolation remain unfinished.

Run `npm test -- --maxWorkers=1`, `npm run lint`, `npm run typecheck`, `npm run contracts:check` and `npm run build`. `npm run test:e2e` requires Chrome or Edge and an independently verified disposable test setup: frontend `http://127.0.0.1:13300`, backend `http://127.0.0.1:15440`, backend connected only to a disposable PostgreSQL database. Set `RPF_E2E_FRONTEND`, `RPF_E2E_BACKEND` and `RPF_E2E_DISPOSABLE_CONFIRMED=1`; optionally set `RPF_E2E_CHROME` to the browser executable. The test creates a synthetic account. Never target a development or production database. The test does not establish runner isolation.
